# 6. FT300 与摩擦补偿

## 6.1 FT300 坐标系

FT300 的原始 wrench 表达在 `ft_frame`。控制器每个周期使用 URDF/KDL 求得 $^B T_S$，并变换为基坐标系：

$$
f_B=R_{BS}f_S,\qquad
\tau_B=R_{BS}\tau_S+p_{BS}\times f_B
$$

因此 `max_measured_wrench` 永远在 `base_frame` 中解释。装配偏移、`ft_frame` 名称或 URDF 固定关节错误都会导致错误保护方向，实机前必须校验。

FT300 是可选功能。`use_external_ft: false` 时控制器不请求传感器状态接口，仍可在没有外置传感器的机械臂上运行。

## 6.2 摩擦补偿边界

UR 官方 `friction_model_controller` 独占 `friction_model/viscous_*`、`friction_model/coulomb_*` 与异步确认接口，并在 direct torque 模式为机器人内部摩擦模型设置比例。笛卡尔阻抗控制器仅独占六个关节 `effort` 接口，二者可以同时 active。

不要在本控制器追加粘性或库仑摩擦公式；否则会与 UR 内部补偿叠加。也不要把 JointState 的 `effort` 当作实际关节力矩，UR 官方说明该字段是电机电流。

在接触任务前，按 FT300 驱动的标定/归零流程消除传感器偏置，并以已知单轴载荷验证 `base_frame` 下的力和力矩符号。

当前 FT300 硬件驱动在激活时提供以下归零服务；应在空载、无接触时调用：

```bash
ros2 service call /io_and_status_controller/zero_ftsensor std_srvs/srv/Trigger "{}"
```
