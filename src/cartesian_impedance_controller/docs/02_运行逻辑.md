# 2. 控制器完整运行逻辑

## 2.1 控制器定位

`cartesian_impedance_controller` 是一个 ROS 2 Control 六自由度笛卡尔阻抗控制器。它独占机械臂六个关节的
`effort` 命令接口，最终由 Universal Robots ROS 2 Driver 通过 `direct_torque(...)` 向机器人发送关节力矩。

本控制器不使用 UR 的 Force Mode 命令接口。`force_mode_controller` 是另一套独立的力位混合控制方案，不能与本控制器同时作为运动控制器激活。

控制器的软件输出不包含重力补偿。UR 在 direct torque 模式中执行内部重力补偿；本控制器可选加入零重力 KDL 模型计算的
科里奥利/离心项，避免重复添加重力力矩。

## 2.2 总体数据流

```text
PoseStamped 目标位姿
        │
        ▼
非实时校验 ─► RealtimeBuffer ─► 超时判断 ─► 位姿参考限速 ─┐
                                                            │
关节 position ─► KDL FK ───────────────► 当前 TCP 位姿 ────┼─► 6D 位姿误差
关节 velocity ─► J(q)qdot ─────────────► 当前 TCP twist ───┤
                                                            │
相邻参考位姿 ───────────────────────────► 期望 TCP twist ───┘
                                                            │
                                                            ▼
                                      K·e + D·(xdot_d-xdot) + Ki·eI
                                                            │
                                                            ▼
                                                Cartesian wrench 限幅
                                                            │
                                                            ▼
                                                   J(q)^T · wrench
                                                            │
                    q、qdot ─► C(q,qdot)，gravity=0 ─────────┤
                                                            ▼
                                           关节力矩绝对值/变化率限幅
                                                            │
                                                            ▼
                                                 六关节 effort 命令

FT300（可选）─► sensor frame wrench ─► base_frame wrench ─► 有效性/超限检查
                                                                  │
                                                                  └─► 故障时六轴零力矩
```

FT300 不参与阻抗 wrench 的计算，只作为可选安全监测输入。因此不安装 FT300 时，将 `use_external_ft` 设置为 `false`，
控制器仍可正常运行。

## 2.3 ROS 2 Control 接口

### 2.3.1 命令接口

控制器按照 `joints` 参数顺序申请：

```text
<joint_1>/effort
...
<joint_6>/effort
```

配置阶段会遍历 `base_frame → tip_frame` KDL 链中的非固定关节，并验证关节数量、名称和顺序与 `joints` 参数完全一致。
验证失败时控制器拒绝配置，防止 Jacobian 列顺序与实际 effort 输出顺序不一致。

### 2.3.2 关节状态接口

控制器按照相同关节顺序申请：

```text
<joint_1>/position ... <joint_6>/position
<joint_1>/velocity ... <joint_6>/velocity
```

任一状态接口不可读或包含 NaN/Inf 时，本周期写入六轴零力矩并返回 `ERROR`。

### 2.3.3 可选 FT300 状态接口

启用 `use_external_ft` 后额外申请：

```text
<ft_sensor_name>/force.x
<ft_sensor_name>/force.y
<ft_sensor_name>/force.z
<ft_sensor_name>/torque.x
<ft_sensor_name>/torque.y
<ft_sensor_name>/torque.z
```

控制器同时要求 URDF 能建立 `base_frame → ft_frame` KDL 链，而且该链中的活动关节必须与机械臂关节同名同序。

## 2.4 生命周期

### 2.4.1 初始化 `on_init()`

声明关节、坐标系、K/D/Ki、参考限速、工作空间、关节边界、wrench/torque 限值和可选 FT300 参数。

### 2.4.2 配置 `on_configure()`

1. 读取并验证所有参数维度、有限性、上下界关系和非负约束。
2. 从 controller manager 提供的 `robot_description` 解析 KDL Tree。
3. 建立 TCP 链，校验六关节名称和顺序。
4. 创建 FK、Jacobian 和零重力动力学求解器。
5. 启用 FT300 时建立传感器链并校验关节顺序。
6. 预分配实时周期使用的 KDL/Eigen 缓冲区。
7. 创建目标位姿订阅，把合法目标写入 `RealtimeBuffer`。

配置失败不会申请并输出运动力矩。

### 2.4.3 激活 `on_activate()`

1. 读取当前六关节位置和速度。
2. 计算当前 TCP 位姿。
3. 将当前位姿同时设置为内部参考位姿和保持位姿。
4. 清零积分状态、目标序号和上一周期力矩。
5. 清除激活前收到的旧目标。
6. 向六个 effort 接口写零。

因此控制器激活时不会直接追踪历史目标，也不会继承上一次运行的力矩变化率状态。

### 2.4.4 停用 `on_deactivate()`

控制器向全部 effort 接口写零，并清零积分状态和上一周期力矩。切换回位置、速度或轨迹控制器时，应由 controller manager
以严格模式完成互斥切换。

## 2.5 目标位姿处理

目标消息类型为 `geometry_msgs/msg/PoseStamped`。

非实时订阅回调执行以下检查：

1. `header.frame_id` 必须为空或等于带 `tf_prefix` 的 `base_frame`。
2. position 和 quaternion 所有分量必须为有限值。
3. quaternion 范数不能接近零，随后归一化。
4. 目标 position 必须位于配置的 x/y/z 工作空间内。

合法目标记录接收时间和递增序号后写入 `RealtimeBuffer`。实时循环不查询 TF，也不等待 ROS 服务。

## 2.6 目标超时与内部参考

实时周期计算：

\[
t_{age}=t_{update}-t_{received}
\]

只有满足 `t_age >= 0` 且 `command_timeout == 0` 或 `t_age <= command_timeout` 的目标才有效。时钟回拨产生负年龄时，
目标不会被当作新鲜命令。

目标有效时，内部参考以 `linear_reference_speed` 和 `angular_reference_speed` 限速逼近目标。控制器使用相邻两个内部参考计算
期望 twist，而不是把突变目标直接代入力矩控制律。

目标首次超时时，控制器锁存超时瞬间的实际 TCP 位姿作为保持位姿，并清零积分项。后续周期继续柔性保持该位姿。

重复发布相同或变化很小的目标不会反复清零 Ki。只有第一条目标，或者目标平移/旋转跳变分别超过
`integral_reset_position_threshold`、`integral_reset_orientation_threshold` 时才清零积分状态。

## 2.7 笛卡尔阻抗控制律

### 2.7.1 位姿误差

所有六维任务量统一表达在 `base_frame`。平移误差为：

\[
e_p=p_d-p
\]

姿态误差使用四元数最短路径对应的 SO(3) 旋转向量：

\[
e_R=\log\left(R_dR^T\right)
\]

组合得到：

\[
e_x=\begin{bmatrix}e_p\\e_R\end{bmatrix}
\]

### 2.7.2 末端速度

当前末端 twist 直接由 Jacobian 和关节速度计算：

\[
\dot{x}=J(q)\dot{q}
\]

期望 twist `xdot_d` 由相邻内部参考位姿计算。因此 D 项同时抑制机械臂实际速度，并对内部限速参考提供速度跟随。

### 2.7.3 K/D/Ki wrench

控制器计算：

\[
F_{task}=K_xe_x+D_x(\dot{x}_d-\dot{x})+K_Ie_I
\]

其中：

- `stiffness` 是六轴刚度 K；
- `damping` 是六轴阻尼 D；
- `integral_gain` 是可选 Ki，默认全零；
- `integral_limit` 限制逐轴积分状态。

积分器使用条件 anti-windup：如果候选积分会让某轴已经饱和的 wrench 进一步增大，该轴保留上周期积分值；允许积分朝解除饱和的方向变化。
最终任务 wrench 按 `max_wrench` 逐轴限幅。

### 2.7.4 映射到关节力矩

任务空间 wrench 映射为：

\[
\tau_{task}=J(q)^TF_{task}
\]

若 `use_coriolis=true`，通过重力向量设为零的 KDL `ChainDynParam` 计算：

\[
\tau_{model}=C(q,\dot{q})
\]

最终未限幅力矩为：

\[
\tau_d=J(q)^TF_{task}+C(q,\dot{q})
\]

公式中没有 `g(q)`。UR 驱动进入 direct torque 模式后使用机器人内部重力补偿。

### 2.7.5 关节力矩保护

每轴依次执行：

1. 使用 `max_torque` 限制绝对力矩。
2. 使用 `max_torque_rate × dt` 限制相对上一周期的变化量。
3. 再次应用绝对力矩限制。
4. 向对应 `<joint>/effort` 接口写入结果。

任何安全错误写零时也会清零“上一周期力矩”状态，避免错误恢复或重新激活后继承旧的限速基准。

## 2.8 FT300 坐标统一

FT300 原始 wrench 表达在 `ft_frame`。控制器根据当前关节位置和 URDF/KDL 计算：

\[
{}^BT_S=\begin{bmatrix}R_{BS}&p_{BS}\\0&1\end{bmatrix}
\]

随后把传感器原点处的 wrench 变换到 `base_frame` 原点：

\[
f_B=R_{BS}f_S
\]

\[
\tau_B=R_{BS}\tau_S+p_{BS}\times f_B
\]

力和力矩必须一起变换；仅旋转三个力分量会漏掉参考点平移造成的力矩。

变换后的 wrench 仅与 `max_measured_wrench` 比较。任一分量非有限或超过对应阈值时，控制器写入六轴零力矩并返回 `ERROR`。
FT300 测量值不叠加到 `F_task`，也不改变 K/D/Ki 控制律。

## 2.9 FT300 数据新鲜度限制

当前 `robotiq_ft_sensor_hardware` 只导出六个数值状态接口，不导出样本时间戳、通信健康标志或样本序号。因此本控制器可以检测：

- NaN/Inf；
- 坐标变换失败；
- 超过 `max_measured_wrench`。

但无法区分“稳定不变的真实载荷”和“通信断开后冻结的有限旧值”。所以 FT300 超限逻辑只能作为附加监测，不能作为人员安全功能或唯一的任务停机链路。

若必须把 FT300 作为失效安全触发源，需要先扩展硬件驱动：导出由新传感器报文更新的时间戳/样本序号或健康状态，再由控制器配置独立
FT watchdog；超时或失联必须进入零力矩错误路径。

## 2.10 摩擦补偿职责

摩擦补偿由 UR 官方 `ur_controllers/FrictionModelController` 配置。它独立申请：

```text
friction_model/viscous_*
friction_model/coulomb_*
friction_model/async_success
```

本控制器只申请六关节 effort，不计算粘性摩擦或库仑摩擦力矩。两个控制器可以同时 active，UR 在 direct torque 模式内部应用所配置的
摩擦模型比例。若本控制器再次加入摩擦公式，会产生重复补偿。

## 2.11 单周期执行顺序

`update(time, period)` 严格按以下顺序执行：

1. 读取六关节 position/velocity，检查有限性。
2. FK 计算当前 TCP，检查关节位置和当前 TCP 工作空间。
3. 读取实时目标，执行时钟和命令超时判断。
4. 选择目标或保持位姿，推进限速内部参考。
5. 检查内部参考仍在工作空间内。
6. 计算位姿误差、Jacobian、当前 twist 和期望 twist。
7. 更新带 anti-windup 的积分状态并计算 K/D/Ki wrench。
8. 检查任务 wrench 有限性并执行 `max_wrench` 限幅。
9. 启用 FT300 时完成 wrench 坐标变换和超限检查。
10. 计算 `J^T F`，可选加入不含重力的 `C(q,qdot)`。
11. 检查关节力矩有限性，执行绝对力矩和力矩变化率限制。
12. 按已验证的关节顺序写入六个 effort 接口。

## 2.12 零力矩故障路径

下列任一情况会调用统一的零力矩写入逻辑并返回 `ERROR`：

- 关节状态接口不可读或出现 NaN/Inf；
- FK、Jacobian 或 Coriolis 求解失败；
- 当前关节、当前 TCP 或内部参考超出配置边界；
- task wrench 或最终关节力矩出现非有限值；
- 启用 FT300 后，传感器接口无效、坐标变换失败或 wrench 超限；
- effort 接口数量错误或写入失败。

命令超时本身不会返回 `ERROR`，而是进入当前位姿柔性保持。控制器停用同样写入六轴零力矩。

## 2.13 实时性边界

实时循环中不进行 TF 查询、ROS 服务等待或参数读取。KDL 关节数组、Jacobian、Coriolis 和 Eigen 向量在配置阶段预分配并循环复用。
目标消息通过 `RealtimeBuffer` 从非实时订阅线程传入。

日志、控制器切换、FT300 归零和摩擦模型参数设置均位于实时循环之外。

## 2.14 控制器兼容关系

- 本控制器与位置、速度、轨迹、`forward_effort_controller`、`force_mode_controller` 互斥。
- `friction_model_controller` 可以同时 active，并只影响 UR 内部 direct torque 摩擦补偿。
- 状态广播器和只读传感器广播器可以同时 active。
- 切换运动控制器时应使用 controller manager 的严格模式，避免两个运动控制器同时占用命令接口。

## 2.15 实机启动原则

首次实机验证应保持 `integral_gain=0`，从较小 K/D、`max_wrench`、`max_torque` 和 `max_torque_rate` 开始；先关闭 FT300 和
Coriolis 验证关节顺序、笛卡尔方向与急停，再逐项启用模型项、官方摩擦补偿和 FT300 附加监测。

软件限幅不能替代 UR 安全配置、保护停止、机械限位、急停以及经过批准的实机风险评估。
