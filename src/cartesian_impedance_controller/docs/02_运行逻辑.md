# 2. 控制器运行逻辑

## 2.1 数据流

```text
PoseStamped 目标位姿 ─► 实时缓冲区 ─┐
关节位置状态 ─► KDL 正运动学 ───────┼─► 位姿误差 ─► K × 误差 ─► wrench 限幅 ─► UR Force Mode
FT300 六轴状态（可选）─► KDL/URDF 坐标变换 ─┘                         │
                                                               └─► 外力反馈修正与超限保护
```

订阅回调运行在非实时 ROS 回调线程中，只验证并写入 `RealtimeBuffer`。`update()` 在 controller manager 控制周期中读取该缓冲区；该路径不查询 TF，也不等待 ROS 服务。

## 2.2 生命周期

1. `on_init()` 声明参数。
2. `on_configure()` 读取参数，从 `robot_description` 构建 `base_frame → tip_frame` KDL 链；启用 FT 时额外构建 `base_frame → ft_frame` 链，并创建目标位姿订阅。
3. `on_activate()` 清除旧目标。激活后，在收到第一条有效目标前不会发送新的 Force Mode 命令。
4. `update()` 根据最新目标、关节位置和可选 FT300 读数计算并写入命令。
5. `on_deactivate()` 写入 `disable_cmd`，请求 UR 结束 Force Mode。

## 2.3 位姿到 wrench 的计算

目标姿态必须在 `base_frame` 中表达。设实际 TCP 位姿为 `T_actual`，目标位姿为 `T_target`：

\[
e = [p_{target}-p_{actual},\; \log(R_{target}R_{actual}^{-1})]
\]

逐轴控制命令为：

\[
w_{spring,i}=\operatorname{clamp}(K_i e_i,-w_{max,i},w_{max,i})
\]

若启用 FT300，则控制器再计算：

\[
w_{cmd,i}=\operatorname{clamp}(w_{spring,i}-g_{ft}w_{measured,i},-w_{max,i},w_{max,i})
\]

其中 `force_feedback_gain` 即 \(g_{ft}\)。默认值为 `0.0`，因此首次实机运行不会因未验证的传感器符号引入闭环修正。

## 2.4 FT300 坐标统一

传感器原始读数的坐标系为 `ft_frame`，默认 `robotiq_ft_frame_id`。控制器根据 URDF 和当前关节位置计算 `T_base_sensor`，并执行完整 wrench 变换：

\[
F_b=R_{bs}F_s,\qquad \tau_b=R_{bs}\tau_s+p_{bs}\times F_b
\]

因此力矩不仅旋转，也会根据传感器原点到 `base_frame` 原点的平移补偿。不要仅手工交换或翻转力的三个分量。

## 2.5 UR Force Mode 写入

每个控制周期写入任务坐标系（当前固定为 `base_frame` 原点）、六轴选择向量、期望 wrench、速度/偏差限制、阻尼和增益。选择向量为 `true` 的轴使用 `speed_limits`；为 `false` 的轴使用 `deviation_limits`。
