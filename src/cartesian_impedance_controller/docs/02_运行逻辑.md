# 2. 运行逻辑

控制器独占六个 `<joint>/effort` 命令接口，并读取同一顺序的 position、velocity 状态接口。UR Driver 通过
`direct_torque(...)` 将其输出发送给机器人。

```text
PoseStamped target_pose
        │
        ▼
合法性校验 → 锁存目标 → 一阶滤波 → 速度硬限幅 → 位姿/速度误差
                                                   │
q, qdot → FK、J(q)、J(q)qdot ─────────────────────┤
                                                   ▼
                         K·e + D·(xdot_ref - xdot) + Ki·∫e
                                                   │
                                    wrench 限幅 → J(q)ᵀ → C(q,qdot)
                                                   │
                                      关节力矩/变化率限幅 → 六轴 effort
```

## 2.1 坐标系与目标

- 当前控制末端为 UR 原始法兰坐标系 `tool0`，基坐标系为 `base`。
- 唯一运动命令入口为 `/cartesian_impedance_controller/target_pose`，类型为
  `geometry_msgs/msg/PoseStamped`，使用 `RELIABLE` QoS。
- `header.frame_id` 必须为空或为 `base`；目标必须在 `workspace_min/max` 范围内，四元数必须有效。
- 合法目标会锁存，直到下一条合法目标覆盖；控制器不会因时间超时取消目标。
- `/cartesian_impedance_controller/current_pose` 是控制器按同一 `base → tool0` KDL 链计算的当前位姿。

## 2.2 参考轨迹

每周期先执行一阶低通，再进行速度硬限幅：

$$
x_f=\alpha x_{target}+(1-\alpha)x_{ref}
$$

平移使用线性插值，姿态使用四元数 slerp。`reference_filter_alpha=0` 保持当前参考，`1` 关闭滤波；
`linear_reference_speed`、`angular_reference_speed` 无论 alpha 取值都生效。

## 2.3 阻抗与保护

$$
\tau=J(q)^T[K e+D(\dot{x}_{ref}-\dot{x})+K_I\int e]+C(q,\dot q)
$$

- KDL 只计算零重力模型的 `C(q,qdot)`；不在软件中添加重力项。
- UR 控制柜负责自身的重力补偿。安装 FT300、夹爪和工件后，仍须在 UR 中正确配置 payload 的总质量与重心。
- `max_wrench`、`max_torque`、`max_torque_rate` 依次限制输出。
- 状态无效、运动学/动力学计算失败、工作空间越界、外部 FT 超限或接口写入失败时，控制器写入六轴零力矩并返回错误，controller manager 会将其停用。

## 2.4 FT300 和摩擦补偿

`use_external_ft=true` 时，FT300 wrench 会变换至 `base` 后仅用于安全阈值检查，不直接进入阻抗控制律。
摩擦补偿由官方 `friction_model_controller` 负责；本控制器不重复计算摩擦补偿。

详细参数见 [`04_参数与安全.md`](04_参数与安全.md)，FT300 部署说明见
[`06_FT300与摩擦补偿.md`](06_FT300与摩擦补偿.md)。
