# 4. 参数与安全

所有六维数组使用 `[x, y, z, rx, ry, rz]` 顺序；关节力矩数组按 `joints` 顺序。

| 参数 | 作用 |
| --- | --- |
| `save_debug_log` | bool，默认 `false`；开启时以 5 Hz 保存控制计算数据 CSV。 |
| `tf_prefix` | URDF 关节和坐标系名称的前缀。 |
| `base_frame` / `tip_frame` | KDL 链起点及控制末端；真机通常为 `base` / `tool0`。 |
| `target_topic` | 绝对目标位姿话题，默认 `~/target_pose`。 |
| `joints` | 六个关节名称，顺序必须与 KDL 链一致。 |
| `stiffness` | 六维比例增益；平移 N/m、旋转 Nm/rad。 |
| `damping` | 六维阻尼增益；平移 Ns/m、旋转 Nms/rad；作用于实测 $J\dot q$。 |
| `max_pose_error` | 每周期参与计算的位姿误差逐轴上限；平移 m、旋转 rad。它限制计算用误差，不限制绝对目标的可达距离。 |
| `max_wrench` | $K e_c-DJ\dot q$ 之后的任务 wrench 逐轴幅值上限；前三项 N、后三项 Nm。 |
| `max_torque` | 加入 Coriolis 后最终六个关节的力矩幅值上限，单位 Nm。 |
| `reference_filter_alpha` | 每周期一阶低通系数，范围 `[0,1]`；`0` 保持参考不变，`1` 直接使用目标。 |

`reference_filter_alpha` 是 ROS 浮点参数，YAML 中应写 `0.0`、`0.5`、`1.0`，不能写整数 `0` 或 `1`。六维浮点数组也应使用带小数点的数值。整数与浮点参数类型不匹配会在初始化阶段导致控制器加载失败，即使数值位于合法范围内。

若 Xbot 持续显示“等待阻抗控制器 / 控制器=未知 / 目标已发布=0”，先检查 Home 终端是否出现 `Failed loading controller`，并查看对应 controller_manager 的日志。此时手柄输入可以正常到达，但目标没有发给控制器，不应通过增大刚度排查。修正后需要重新加载控制器；当前流程需重启 Home 与 teleop，单独重启 teleop 不会重新加载失败的控制器。

增益和三层限幅必须为六个有限非负数，`reference_filter_alpha` 必须有限且位于 `[0,1]`。配置错误时控制器配置失败。Coriolis 固定启用，KDL 模型使用零重力向量。

本包另外提供低、中、高三档真机 K/D 参数文件；数值、共用限幅和使用方法见[刚度阻尼三档配置](07_刚度阻尼三档配置.md)。原有 `ur10e_ft300_cartesian_impedance.yaml` 保持独立，启动入口仍默认使用该文件。

控制器参数由本包 `config/` 提供。`ur10e_ft300_cartesian_impedance.yaml` 沿用原文件名，但控制律已不依赖 FT300；`ur10e_xbot_sim_cartesian_impedance.yaml` 用于仿真。是否启动 FT300 和夹爪由启动入口选择。

三层限幅只约束控制器输出。绝对目标可远于当前位姿，持续锁存后机器人仍会逐步向目标运动；运行前须确认目标、路径和 UR 控制柜的安全限制。`max_torque_rate` 已移除，因此力矩可能在相邻周期发生较大变化；首次测试应谨慎调低刚度和上限并现场监控。

## 保存控制计算调试数据

在实际加载的笛卡尔阻抗 YAML 中设置：

```yaml
/**/cartesian_impedance_controller:
  ros__parameters:
    save_debug_log: true
```

此开关与 Xbot 顶层 `debug` 控制的终端日志独立。五份控制器示例配置均提供该字段，默认为 `false`；关闭时不创建文件或保存定时器。编译新代码后，重启 Home 与 teleop 以重新加载控制器和参数。

开启后启动终端显示文件路径：`/ros2_ws/log/cartesian_impedance_controller/debug-<纳秒时间戳>.csv`，每次 configure 创建新文件。文件开头记录基座/末端、实际 K/D、滤波系数及各级限幅。其后各行包含：

- `time_ns`：控制周期 ROS 时间戳；`target_sequence`：该周期实际应用的目标序号。
- `current`、`target`、`reference`：控制器 KDL 实测、锁存目标和滤波后参考，按 xyz+xyzw 排列。
- `error_raw`、`error`：滤波参考相对实测的原始误差、逐轴限幅后的误差。
- `twist`、`spring`、`damper`：实测笛卡尔速度、K×error、−D×twist。
- `wrench_raw`、`wrench`：任务力/力矩限幅前后值。
- `torque_task`、`coriolis`、`torque_raw`、`torque`：Jᵀ×wrench、Coriolis、相加结果及最终限幅力矩。
- `write_ok`：六关节 effort 接口写入是否均成功。若失败，该周期随后尝试写零；此字段不能证明驱动已经将力矩发送或控制柜已经执行。

六维笛卡尔列后缀 `_0` 至 `_5` 对应 x/y/z/rx/ry/rz，单位分别为 m/rad、m/s 与 rad/s、N/Nm；关节力矩列按 YAML `joints` 顺序，单位 Nm。比较限幅前后字段即可判断哪一级饱和。

实时循环只用 `try_lock` 交出固定大小快照，忙时跳过，不执行格式化或文件写入。非实时定时器每 0.2 秒写入并刷新最新快照；这是约 5 Hz 的抽样日志，不是完整 500 Hz 数据，不能用于排除短时尖峰。相同快照不重复写入，正常保持期间新的控制周期仍会被抽样；计算提前失败的周期不包含完整计算记录，需结合控制器错误日志分析。文件写入失败会打印错误并停止保存，不更改控制律。
