# 独立启动与键盘测试

`standalone_real.launch.py` 从本功能包启动 UR 真机驱动、组合机器人描述和笛卡尔阻抗控制器，不启动 `ur_teleop`。默认不启动 Robotiq 夹爪控制栈；FT300 保留组合模型与虚拟 `ros2_control` 接口，但不连接传感器串口。控制器激活时以实测 `tool0` 位姿为初始保持目标。

## 启动

确认机器人示教器中的 External Control 程序可用，机器人附近有人监护且运动空间无障碍。先停止已运行的 UR 驱动、`/controller_manager`、Xbot 遥操作和其他目标位姿发布者，避免两个进程同时控制同一机器人。

终端 1：

```bash
source /opt/ros/jazzy/setup.bash
source /ros2_ws/install/setup.bash
ros2 launch cartesian_impedance_controller standalone_real.launch.py \
  robot_ip:=169.254.138.15 \
  use_gripper:=false use_ft300:=false launch_rviz:=false
```

`robot_ip` 必填。`use_gripper:=false` 不启动独立夹爪控制栈；`use_ft300:=false` 将 FT300 硬件设为虚拟模式，不访问 `ttyUSB` 串口。组合模型中的 FT300 和夹爪连杆仍保留，控制末端仍为 UR 法兰 `tool0`。需要真实设备时可分别设 `use_gripper:=true gripper_com_port:=/dev/ttyUSB0`、`use_ft300:=true ft_sensor_ftdi_id:=ttyUSB2`。启用真实 FT300 只表示连接传感器；控制器参数文件中的 `use_external_ft: false` 仍使外部力监测保持关闭，启用前需单独检查参数和传感器状态。

本入口复用 `ur10e_robotiq_ft_description/real_bringup.launch.py`。它会将轨迹控制器保持 inactive，并加载、激活 `cartesian_impedance_controller`。终端 1 必须保持运行。

## 启动后确认

在终端 2 加载相同 ROS 环境和 `ROS_DOMAIN_ID`，先检查：

```bash
ros2 control list_controllers -c /controller_manager
ros2 control list_hardware_interfaces -c /controller_manager | rg '/effort'
ros2 topic echo /cartesian_impedance_controller/current_pose --once
```

应看到笛卡尔阻抗控制器 `active`、UR 六关节的 `effort` 接口为 `[claimed]`，以及坐标系为 `base` 的有效 `current_pose`。如果控制器不是 active 或当前位姿无效，先检查终端 1 的驱动与控制器日志，不发送键盘目标。

## 键盘发送小步目标

终端 2 使用显式的 2 mm 步长和 10 mm 单步上限：

```bash
/usr/bin/python3 /ros2_ws/src/cartesian_impedance_controller/src/keyboard_target_pose.py \
  --frame base --step 0.002 --max-lead 0.01
```

`W/S` 为 X 正/负，`D/A` 为 Y 正/负，`R/F` 为 Z 正/负；空格将当前实测位姿设为保持目标，`Q` 退出。工具每次按键都从最新实测 `tool0` 位置生成单步目标，要求交互式终端，并在存在其他目标发布者时拒绝发布。**当前工作区键盘脚本的默认步长为 0.02 m，测试时应显式传入上面的 `--step`。**退出脚本后控制器仍会保持最后目标；结束测试时停止终端 1 的 launch。

控制器收到有效命令时会在终端 1 输出“已接收目标 pose”。若键盘工具显示目标但机器人不动，同时检查 `current_pose`、控制器状态、机器人程序和安全状态；不要靠重复按键叠加目标。控制器的其他参数与保护范围见[参数与安全](04_参数与安全.md)。
