# 3. 使用方式

本页给出独立启动 UR10e 笛卡尔阻抗控制器、检查状态和使用键盘发送小步目标的完整命令。控制器接收**绝对目标位姿**；控制律和三层限幅见[运行逻辑](02_运行逻辑.md)，独立启动参数说明见[独立启动与键盘测试](05_独立启动与键盘测试.md)。

## 3.1 构建

```bash
cd /ros2_ws
source /opt/ros/jazzy/setup.bash
colcon build --packages-select \
  ur_robot_driver \
  ur10e_robotiq_ft_description \
  cartesian_impedance_controller
source install/setup.bash
```

若激活的 Python 虚拟环境缺少 `catkin_pkg`，构建时显式使用系统解释器：

```bash
colcon build --packages-select cartesian_impedance_controller \
  --cmake-args -DPython3_EXECUTABLE=/usr/bin/python3
```

## 3.2 实机独立启动

先确认示教器 External Control 程序可用、现场有人监护，并停止其他 UR 驱动、`/controller_manager` 和目标发布进程。终端 1 执行；默认不启动 Robotiq 夹爪，也不连接真实 FT300 串口：

```bash
source /opt/ros/jazzy/setup.bash
source /ros2_ws/install/setup.bash
ros2 launch cartesian_impedance_controller standalone_real.launch.py \
  robot_ip:=169.254.138.15 \
  use_gripper:=false use_ft300:=false launch_rviz:=false
```

将 `robot_ip` 改为当前机器人地址。`use_gripper`、`use_ft300` 可分别设为 `true`；关闭 FT300 时启动入口使用虚拟传感器接口，不访问其串口。当前控制器只申请关节位置和速度状态，不读取 FT300。组合 URDF 仍保留传感器和夹爪的连杆，控制末端为 `tool0`。终端 1 需保持运行。

已有组合系统也可使用以下入口；它会尝试连接所指定的 FT300 和夹爪，只有设备就绪时才运行：

```bash
source /opt/ros/jazzy/setup.bash
source /ros2_ws/install/setup.bash

ros2 launch ur10e_robotiq_ft_description real_bringup.launch.py \
  robot_ip:=<机械臂IP> \
  ft_sensor_ftdi_id:=<FT300设备名> \
  gripper_com_port:=/dev/ttyUSB0 \
  use_cartesian_impedance:=true
```

`use_cartesian_impedance` 默认就是 `true`。两个入口都会将
`scaled_joint_trajectory_controller` 保持为 inactive，并加载、配置、激活
`cartesian_impedance_controller`。启动日志必须包含：

```text
spawner_cartesian_impedance_controller ... Configured and activated cartesian_impedance_controller
```

终端 2 加载相同 ROS 环境后，确认状态、接口归属和当前位姿：

```bash
source /opt/ros/jazzy/setup.bash
source /ros2_ws/install/setup.bash
ros2 control list_controllers -c /controller_manager
ros2 control list_hardware_interfaces -c /controller_manager | rg '/effort'
ros2 topic echo /cartesian_impedance_controller/current_pose --once
```

必须看到：

```text
cartesian_impedance_controller ... active
shoulder_pan_joint/effort ... [claimed]
...
wrist_3_joint/effort ... [claimed]
```

若控制器显示 `inactive`、effort 为 `[unclaimed]`，或没有有效的 `current_pose`，先查看终端 1 中 `spawner_cartesian_impedance_controller` 和驱动的输出，不要发布目标。

## 3.3 目标位姿命令

控制器只接收一个笛卡尔命令话题：

```text
/cartesian_impedance_controller/target_pose
类型：geometry_msgs/msg/PoseStamped
QoS：RELIABLE
坐标系：base
末端：tool0
```

目标为绝对 pose，并会一直保持到下一条合法目标覆盖。下面是特定起始位姿的示例；执行前必须从 `current_pose` 读取本机当前位姿，确认目标和运动空间，不能直接把示例数值用于其他起点：

```bash
ros2 topic pub --once --qos-reliability reliable \
  /cartesian_impedance_controller/target_pose \
  geometry_msgs/msg/PoseStamped \
  "{header: {frame_id: base}, pose: {position: {x: 0.16769641280231273, y: -0.6362602994068254, z: 0.45386373242816435}, orientation: {x: 0.7230276088907228, y: 0.6898639992269759, z: -0.02797790031613137, w: 0.02315116511597808}}}"
```

出现 `publishing #1` 才代表消息已发送。首次启动出现等待订阅者是 DDS 发现过程，应等待，不要在消息发送前中断。

控制器收到通过坐标系、有限数值和四元数合法性校验的 `target_pose` 后，会在终端 1 以最多 5 Hz 输出“已接收目标 pose”，包含 `xyz+xyzw` 和接收序号。该日志表示目标已写入缓冲区；如只有上游“目标已发布”而没有此日志，请检查话题、QoS、坐标系及控制器的拒收警告。当前控制器不做 workspace 检查；`max_pose_error` 只限制每周期参与计算的误差，**不会截断或取消绝对目标**。

## 3.4 单轴相对测试和键盘控制

`move_base_xyz` 读取 `/cartesian_impedance_controller/current_pose`，生成相对当前 `tool0` 的 base 单轴目标，
仍只发布到 `target_pose`：

```bash
ros2 run cartesian_impedance_controller move_base_xyz z 0.01
```

支持 `x`、`y`、`z`、`x+`、`x-` 等形式；单次绝对位移上限为 `0.10 m`。工具会发布
`/cartesian_impedance_controller/base_xyz_error`，其中“稳定”不表示已经到达目标，必须检查误差范数。

推荐在终端 2 使用键盘工具做首次小步测试。该工具同样只发布 `target_pose`；显式指定 2 mm 步长和 10 mm 单步上限：

```bash
/usr/bin/python3 /ros2_ws/src/cartesian_impedance_controller/src/keyboard_target_pose.py \
  --frame base --step 0.002 --max-lead 0.01
```

按键：`W/S` 为 X 正/负，`D/A` 为 Y 正/负，`R/F` 为 Z 正/负，空格为保持当前位姿，`Q` 退出。
每次有效按键都以最新 `/cartesian_impedance_controller/current_pose` 的 `tool0` **实测位置**为起点，仅在指定的 `base` 轴增加或减少 `--step`；按住按键产生的重复事件不会把增量累计到上一次目标。目标姿态在首次按键时锁存，空格会用当前实测位姿和姿态重新锁存。`--step` 才是每键位移，`--max-lead` 只是单步目标相对实测位置的安全上限，必须满足 `--step <= --max-lead`。若机器人停滞，重复按键不会继续把目标推远；在当前平移刚度 500 N/m 下，5 mm 误差的纯弹簧项约为 2.5 N，可能不足以克服实际阻力。此工具用于隔离测试，不代替标定和阻抗参数排查。

键盘工具在每次按键前检查目标话题的发布者数量；若还有其他键盘工具或 Xbot 发布目标，会拒绝本次发布。启动前也应退出旧键盘进程，确保目标话题只有一个发布者。终端反复显示相同目标，表示最新实测位置没有向该方向前进，重复按键不会继续增加目标位移；应同时查看 `current_pose`、控制器运行状态和机器人安全状态。

键盘脚本当前默认步长为 0.02 m，因此首次测试务必显式传入上面的 `--step 0.002`。按 `Q` 退出后，控制器仍保持最后的绝对目标；结束测试时停止终端 1 的 launch。

## 3.5 安全边界

- 不得同时激活位置、速度、轨迹、`forward_effort_controller` 或 `force_mode_controller`。
- 在 PolyScope 中正确设置包含 FT300、夹爪和工件的 payload 总质量与重心；这不是 URDF 自动完成的配置。
- 初次实机测试从小位移和保守 K/D、`max_pose_error`、`max_wrench`、`max_torque` 限制开始；当前控制器不读取 FT300。
- 始终保留急停、保护停止和现场监视；软件限幅不替代机器人安全配置。

要恢复官方轨迹控制，可在组合入口显式传入 `use_cartesian_impedance:=false`，或先退出目标发布进程，再严格切换控制器：

```bash
ros2 control switch_controllers \
  --deactivate cartesian_impedance_controller \
  --activate scaled_joint_trajectory_controller \
  --strict -c /controller_manager
```
