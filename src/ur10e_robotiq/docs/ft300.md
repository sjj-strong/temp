# FT300 Mock 链路

## 当前能力边界

当前项目只验证 Robotiq FT300 的 **Mock 软件链路**。组合 Xacro 在
`use_fake_mode:=true` 时仍加载真实的
`robotiq_ft_sensor_hardware/RobotiqFTSensorHardware` 插件，但插件的 `read()`
固定写出六个 `0.0`：

- `force.x`、`force.y`、`force.z`
- `torque.x`、`torque.y`、`torque.z`

因此，收到六维零值 `WrenchStamped` 只能证明 Xacro、hardware component、state
interface、broadcaster 和 ROS topic 已经连通。它不能表示接触力、载荷、重力、噪声、
零点漂移或真实 FT300 的 USB/串口通信，也不能用于碰撞检测或力控参数整定。

## 实现接口

| 项目 | 当前值 |
| --- | --- |
| hardware component | `robotiq_ft_sensor` |
| hardware plugin | `robotiq_ft_sensor_hardware/RobotiqFTSensorHardware` |
| sensor name | `robotiq_ft_sensor` |
| controller | `robotiq_force_torque_sensor_broadcaster` |
| controller plugin | `force_torque_sensor_broadcaster/ForceTorqueSensorBroadcaster` |
| topic | `/robotiq_force_torque_sensor_broadcaster/wrench` |
| message type | `geometry_msgs/msg/WrenchStamped` |
| frame | `robotiq_ft_frame_id` |

FT300 与 UR10e、Robotiq 2F-85 共享唯一的 `/controller_manager`，没有第二个
`/robotiq_controller_manager`。

## 与 UR 内置 F/T 的区别

Mock 配置中同时存在两条不同语义的 F/T 数据通路：

- `/force_torque_sensor_broadcaster/ft_data` 对应 UR 控制系统内置的
  `tcp_fts_sensor`，frame 为 `tool0_controller`。
- `/robotiq_force_torque_sensor_broadcaster/wrench` 对应安装在法兰和夹爪之间的
  外部 FT300，sensor 为 `robotiq_ft_sensor`，frame 为 `robotiq_ft_frame_id`。

不要因为消息类型相同而互换 topic。MoveIt 的几何模型中 FT300 位于 `tool0` 和
`robotiq_85_base_link` 之间，但当前 Mock wrench 不由几何碰撞计算产生。

## 启动与验证

终端 A：

```bash
source /ros2_ws/install/setup.bash
ros2 launch ur10e_robotiq_description mock_control.launch.py
```

终端 B：

```bash
source /ros2_ws/install/setup.bash
ros2 control list_hardware_components --controller-manager /controller_manager
ros2 control list_hardware_interfaces --controller-manager /controller_manager
ros2 control list_controllers --controller-manager /controller_manager
ros2 topic info /robotiq_force_torque_sensor_broadcaster/wrench -v
ros2 topic echo --once --timeout 10 /robotiq_force_torque_sensor_broadcaster/wrench
```

通过条件：

- `robotiq_ft_sensor` hardware 为 `active`；
- 六个 `robotiq_ft_sensor/{force,torque}.{x,y,z}` state interface 可用；
- `robotiq_force_torque_sensor_broadcaster` 为 `active`；
- topic 只有预期 broadcaster 发布，类型为 `WrenchStamped`；
- 一条消息的 frame 为 `robotiq_ft_frame_id`，六个值均为有限的 `0.0`。

历史验证中 `ros2 topic echo` 曾报告一次采样期消息丢失，但命令退出码为 `0` 且取得
一条完整消息。若持续丢失或无法取得任何消息，应按
[排障指南](troubleshooting.md#ft-wrench-不发布) 检查，而不是把它解释为物理传感器读数。

## 真机切换说明

当前计划没有执行 FT300 真机连接。切换 `use_fake_mode:=false` 会让上游硬件插件尝试
发现或打开 FT300 设备，并引入设备权限、`ftdi_id`、采样周期和归零等真实硬件条件；
这不属于已验证的 Mock 工作流。在完成安装姿态、设备标识、标定与安全评审前，不应把
本文的零值链路验证当作真机验收结果。
